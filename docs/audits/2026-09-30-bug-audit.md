## P1

### P1-1. Ping-pong pinning leaks effect instances — VERIFIED

**Where:** `unicornviz/app.py:9856-9870` (`cut_to_pinned`), driven by
`drop-ins/auto-vj-01/auto_vj.py:9008-9024`.

**What happens:** Auto VJ calls `pin_effect_pair()` (two fresh instances)
and then immediately `cut_to_pinned()`.  That call does
`self._current_effect = pair[which]; self._next_effect = None` without
destroying either old reference:
- The effect that was on screen when ping-pong began is orphaned: its
  programs, textures and FBOs are never released.
- If a transition was in flight, its incoming instance is orphaned too.
- `unpin_effect_pair()` only cleans up the two pinned instances.

Ping-pong auto-starts during normal Auto VJ sets ("Ping-pong AUTO ON"), so
an eight-hour show leaks one or two full effects per entry.  Heavy effects
(ProjectM, video/texture showcases, Sim Showcase) make this real GPU-memory
growth.

**Evidence:** a harness around the real `App.pin_effect_pair` →
`cut_to_pinned('a')` → `cut_to_pinned('b')` → `unpin_effect_pair()` shows
`destroy()` called 0 times on both the pre-ping-pong effect and the
in-flight `_next_effect`.

**Related:** if a pinned effect crashes, `_handle_effect_crash()`
(`app.py:5783`) destroys it but leaves it in `_pinned_pair`.  The next
`cut_to_pinned()` renders a destroyed instance, and `unpin_effect_pair()`
destroys it a second time.

**Fix direction:**
- In `cut_to_pinned`, destroy the outgoing `_current_effect` and
  `_next_effect` when they are not members of the pair.
- In `_handle_effect_crash`, drop a crashed pinned member from the pair (or
  unpin).
- Destroy the off-screen member in `_shutdown_runtime`.
- Add a regression test using the harness above.

### P1-2. Stopping a recording freezes the show

**Where:**
- `unicornviz/recording.py:984-1027` (`stop` → `_await_finalize`).
- Called on the main thread from `App.stop_recording` (`app.py:9285`),
  bound to `V`.
- Also called from `_handle_recording_resize_interruption`
  (`app.py:8539`), which runs on **every** `SDL_WINDOWEVENT_RESIZED` and on
  fullscreen or display-mode changes.

**What happens:** `-movflags +faststart` makes ffmpeg rewrite the whole
file on close.  `_await_finalize` waits for that by design: up to 600 s,
and the code's own docstring says "tens of seconds" for a long set.  All of
that wait is on the render thread, so:
- Pressing `V` to end a long recording freezes the visuals until the
  rewrite finishes.
- Toggling fullscreen or dragging the window edge while recording
  stops, finalizes and restarts the recording, once per resize event.

**Fix direction:**
- Finalize on a worker thread; the render loop only needs "stopping"
  state for the HUD.
- Debounce the resize-triggered rotation, or skip it when the output size
  did not actually change.

### P1-3. A stalled encoder can hang `stop()` for good

**Where:**
- `drop-ins/streaming-01/rtmp_streamer.py:554-598`.
- Same shape in `unicornviz/recording.py:993-1008`.

**What happens:** when the RTMP endpoint (or a wedged hardware encoder)
stops draining, ffmpeg stops reading stdin and the writer thread blocks
inside `proc.stdin.write()` while holding the `BufferedWriter` lock.  Then
`stop()`:
1. joins the writer for 3 s (5 s in the recorder), which times out;
2. calls `proc.stdin.close()`, which needs the same lock, so it blocks
   until ffmpeg reads again, which it may never do.

`stop()` runs on the main thread: from the hotkey, from
`_shutdown_runtime`, and in streaming-01 also from `write_frame()` once a
write failure is flagged.  The whole app hangs exactly when the network
goes bad.  Even without the lock problem, the escalation chain is up to
~19 s of main-thread waiting.

**Fix direction:**
- If the writer is still alive after the join, `proc.kill()` *before*
  touching stdin.
- Move the rest of the teardown off the main thread.

### P1-4. Crash isolation is still partial

The 08-03 P0 ("main loop has no crash isolation") was fixed for effect
`update()`/`render()`/instantiate in `_switch_effect` and for keyboard
hotkeys.  These paths are still unguarded inside `run()`; any exception
propagates out, and `__main__`'s `finally` shuts the app down:
- **Config editor keyboard branch** (`app.py:6742-6825`).
  - `_config_editor_adjust` / `_config_editor_activate` /
    `_config_editor_set_text` call drop-in `set_config_setting()` through
    `_dropin_row_spec`'s `_set` closure (`app.py:5178`) with no guard.
  - `_dropin_row_spec` also does `float(row.get('value'))` unguarded
    (`app.py:5155`), so one drop-in returning `None` breaks spec building.
  - The mouse path for the same actions *is* guarded (`app.py:7011-7023`).
- **MIDI dispatch.**
  - `hotkeys.process_pending_midi()` (`app.py:7125`) →
    `_dispatch_midi_event` (`hotkeys.py:404`) has no try/except.
  - A raising action ends the app and drops the rest of that frame's MIDI
    batch.
- **Render-phase drop-in calls** in `run()` (`app.py:7656-7780`):
  - `_video_deck_layer.update()` and `.draw()`;
  - `_webcam_system.render()`;
  - `_dancing_unicorn.update()` and `.render()`;
  - `_rainbow_nova.update()` and `.render()`;
  - `_grand_finale.render_overlay()`;
  - `_candy_frame.update()` and `.render()`;
  - Auto VJ `render_celebration_overlay()`;
  - `_streamer.write_frame()` (`app.py:7939`).
  - Only subsystem overlays and presents are guarded.
- **Transition completion:** `self._current_effect.destroy()`
  (`app.py:8382`) is unguarded.  A raising `destroy()` kills the app on the
  last frame of a fade.
- **First effect at boot:** `self._instantiate(_first_cls)`
  (`app.py:6551-6553`) is unguarded.  A shader that fails to compile on the
  operator's driver in whichever effect the playlist starts on is a startup
  crash.  The same call inside `_switch_effect` is guarded and quarantines.

**Fix direction:**
- Wrap each of these in the same contain-and-log pattern.
- For per-frame drop-in calls, disable the drop-in after N consecutive
  failures and throttle the log (see P3-6).
- For the first effect, fall back through `_resolve_unblocked_effect`.

### P1-5. Audio analysis thread dies on any exception

**Where:** `unicornviz/audio/manager.py:341-390` (`_analysis_worker`).

**What happens:** the loop calls `maybe_fallback()`,
`set_sample_rate()`, `Analyzer.process()` and `drain_onsets()` with no
try/except.
- Any exception ends the daemon thread; the traceback goes to stderr via
  the threading excepthook.
- From then on `get_audio_data()` returns the last published snapshot
  forever: no bass, no beats, no BPM, no Auto VJ input.
- Nothing notices.  Only the *process* host has death recovery
  (`_recover_audio_in_process`); an in-process or in-helper thread death
  does not.

**Fix direction:**
- Guard the loop body.
- Log once per distinct error.
- Keep running; after repeated failures on the same block shape,
  `set_profile`/reset the analyzer.

### P1-6. Unreadable settings files are silently replaced with empty ones

**Where:**
- `unicornviz/runtime_state.py:28-50`.
- `unicornviz/config_profiles.py:53-66`.

**What happens:**
- `RuntimeStateStore._load()` turns a parse failure into `{}`.
  `_ensure_schema_metadata()` then reports a change, so `__init__`
  **immediately saves**, overwriting the unreadable file.  The config menu
  now holds every setting there (config.toml is being retired), so one
  truncated or hand-mangled byte loses all of them.
- `ConfigProfileStore` does the same on the next profile autosave, writing
  a file that holds only the active profile.
- Neither keeps a backup.

dj-mixer-01's `track_store.rotate_backups()` already solves this:
- rolling `.bak1`/`.bak2` copies;
- refuses to rotate a file that does not parse, or has lost half its
  records.

**Fix direction:**
- On a parse failure, move the file aside as `.corrupt-<ts>` and log at
  ERROR; never overwrite it.
- Adopt the mixer's rolling-backup scheme for both stores.

## P2

### P2-1. `Config.set_override()` corrupts defaults and "file" values — VERIFIED

**Where:** `unicornviz/config.py:409-417, 421, 470-495`.

**What happens:** `self._data = dict(_DEFAULTS)` and `_deep_merge()` are
shallow.  A section the user's TOML doesn't mention is the module-level
`_DEFAULTS[section]` object itself.  A section present only in the TOML is
the same dict object as `self._file_data[section]`.  `set_override()`
mutates in place, so:
- `Config('/none').set_override('audio', 'latency', 'high')` changes
  `_DEFAULTS['audio']['latency']`.  A fresh `Config` then reads `high`,
  and `validate()` type-checks against the corrupted default.
- For a drop-in section in config.toml, `file_value()` returns the override
  (reproduced with `[spotify.web_api] enabled`).  That breaks its
  documented contract ("not a built-in default, CLI flag or in-memory
  override").  The config→menu migration relies on that contract.

**Fix direction:**
- `copy.deepcopy` the defaults and the parsed TOML in `__init__`, or make
  `_deep_merge` copy nested dicts.
- Add a regression test for both reproductions.

### P2-2. videos-01 re-seeks every frame once the playhead passes the end — VERIFIED

**Where:**
- `drop-ins/videos-01/deck_video_source.py:372-389` (`_needs_seek`), with
  `_seek_and_refill` / `_decode_forward`.
- No clamp in `unicornviz/video_deck_layer.py:338-353`.

**What happens:** when the deck position is more than 1.5 s past the
video's duration (audio longer than the video, or a paused deck parked past
the end), the ring can never cover the target.  Every `set_target()` (every
frame) wakes the worker, which does a keyframe seek and decodes to EOF.

**Evidence:** a synthetic 2 s 320×180 clip with the playhead at 10 s did 45
seeks and used 3.4 CPU-seconds in 2 wall-seconds.  A 1080p music video will
be far worse and competes with the render and audio threads.

**Fix direction:**
- Clamp the target to `duration_s` in `set_target` or `_reconcile`.
- Treat "target beyond EOF and ring already holds the last frame" as
  satisfied.

### P2-3. Larger capture blocks truncate the analyzer FFT

**Where:** `unicornviz/audio/analyzer.py:837` (and the side channel at
`:931`).

**What happens:**
- `np.fft.rfft(windowed, n=self._bands * 2)` truncates when the block is
  longer than `2 × fft_bands`.
- The Hann window is sized for the full block, so the FFT sees only the
  *older* half of the block through the rising half of the window.
- The newest audio never reaches the spectrum, flux, onset detection or
  bands.
- `docs/configuration.md` recommends `blocksize = 2048` as the xrun remedy,
  and the config menu exposes `audio_blocksize`.  With the default
  `fft_bands = 512`, following that advice silently degrades the detector.

**Fix direction:** either take `n = max(len(block), 2 × bands)` and
resample to `bands` bins, or FFT the most recent `2 × bands` samples with
a window of that length.  Test at blocksize 512, 1024, 2048 and 4096.

### P2-4. Transitions are hidden under Candy Frame, Rainbow Nova or the Grand Finale overlay

**Where:**
- `unicornviz/app.py:8440` (transition composite target).
- `app.py:7695-7768` (late overlays).

**What happens:**
- During a transition the blend goes straight to the screen unless mirror
  mode, a post chain or video decks are active.
- The late overlays then draw from `fbo_a`, which at that point holds only
  the **outgoing** effect.
- Candy Frame composites with `blend_func = ONE, ZERO` and alpha 1.0
  (`candy_frame_controller.py:554-557`), fully replacing the blend.
- Result: with Candy Frame (or Nova, or the finale overlay) on and no
  post-FX, every transition shows the old effect until it snaps to the new
  one.
- The no-transition branch (`app.py:8271`) includes `candy_active`,
  `nova_active` and `finale_overlay_active` in its FBO condition; the
  transition branch does not.

**Fix direction:** add those three flags to the transition branch's
composite-to-`fbo_a` condition and present from `fbo_a`, as the other
branches do.

### P2-5. Esc during the splash tears SDL/GL down twice

**Where:** `unicornviz/app.py:6182-6189`.

**What happens:** the Esc branch calls `audio_manager.stop()`,
`SDL_GL_DeleteContext` and `SDL_DestroyWindow`, then `SDL_Quit`, and
returns.  It leaves `_gl_context`/`_window` set and `_shutdown_complete`
false.  `__main__`'s `finally: app.ensure_shutdown()` (`__main__.py:634`)
then:
- releases GL objects on the deleted context;
- deletes the context and destroys the window **again**, through freed
  handles;
- calls `audio_manager.stop()` again (so `sd._terminate()` runs twice) and
  saves state.

At best noisy; at worst a segfault on exit.

**Fix direction:** replace the hand teardown with `self._running = False`
plus `return`, or call `self._shutdown_runtime()` and return.

### P2-6. media-01 auto-level touches libvlc volume from a worker thread

**Where:**
- `drop-ins/media-01/media_controller.py:1285-1306` (`_measure` thread).
- → `_VlcBackend.set_track_gain` (`:484-504`).

**What happens:** the backend's rule is that volume is only set from
`tick()` on the main thread, once the player's audio output is live.  The
`--aout=pulse` note and `_output_is_live` document a SIGSEGV when
`audio_set_volume` races output creation.  `set_track_gain` breaks that
rule on this path:
- It checks `get_time() > 0` and then calls `audio_set_volume` directly
  from the measurement thread.
- If the main thread `play()`s a new track or flips `_active` for a
  crossfade between the check and the call, that is the race.
- Even without a crash, the old track's gain can land on the newly active
  player: `_gains[self._active]` is read after the token check.

**Fix direction:** have the worker store `(token, gain)` only; apply it in
`tick()` on the main thread after re-checking the token.

### P2-7. Hotkey rebinds leak the old key and don't detect most conflicts

**Where:**
- `unicornviz/hotkeys.py:229-247` (`translate_override_chord`).
- `unicornviz/app.py:3958-4001`.

**What happens:**
- A rebind only maps the *new* chord onto the action's default chord
  before the unchanged dispatch chain runs.  The default chord still
  matches, so after rebinding `disable_and_advance` away from `Delete`,
  `Delete` still disables the current effect.
- Conflict detection checks only the ~30 named actions.  Binding an action
  to a chord that `handle()` or a drop-in key handler already uses (for
  example `V`, recording) passes the check and silently shadows it.
- `audio_toggle` and `eq` are both defined as `E` (`hotkeys.py:186-187`);
  the help audit warning in the core suite flags the same thing.

**Fix direction:**
- When an override exists for an action, swallow that action's default
  chord unless another action is bound to it.
- Build conflict detection from the full dispatch table plus registered
  drop-in `HELP_ENTRIES`.

### P2-8. Audio-scaled `iTime` makes shader phases jump (carried over, still open)

This is the 08-03 "Class A" item, never fixed.  `BaseEffect.time` starts at
`rng.uniform(0, 10000)` (`effects/base.py:321`).  A shader term
`iTime * (a + iBeat * k)` therefore moves by `iTime · k · Δbeat`, i.e.
thousands of radians, whenever the audio value changes.  Sweeps, hues and
swirls teleport to random phases on each beat or bass change instead of
speeding up.

Still present (14 sites in 10 files):
- `unicornviz/effects/`: `audio_spectrum.py:139`,
  `audio_spectrogram.py:85`, `audio_tracks.py:105`,
  `audio_waveforms.py:102`.
- `effects-tech/cyber_war.py:102-105` (×4).
- `effects-feature/metaballs.py:68,72`.
- `effects-feature/rainbow_trance.py:119`.
- `unicorn-tears-01/unicorn_tears.py:191`.
- `webcam-01/webcam_overlay.py:346`.
- `projectm-01/projectm_effect.py:232`.

**Fix direction:** integrate a phase on the CPU
(`self._phase += dt * (a + k * audio)`) and pass it as a uniform.

### P2-9. spotify-01: no refresh on 401; token path ignores `UNICORNVIZ_APP_ROOT`

**Where:** `drop-ins/spotify-01/spotify_controller.py:927-928, 773-808`.

- **401:** only sets `_auth_status = 'token_expired'`.  `_auth_ready` and
  `_token_expires_at` stay unchanged, so `_poll_worker` sees a "valid"
  token and keeps 401-ing until the local expiry (up to an hour).  A
  revoked or server-invalidated token looks like silent Spotify
  data loss.  CLAUDE.md requires refresh logic "so auth does not silently
  expire".
  - *Fix:* on 401, set `_token_expires_at = 0` so the next poll refreshes.
- **Token path:** relative paths resolve from `__file__.parents[2]`, not
  `UNICORNVIZ_APP_ROOT`.  This is the 09-05 O11 class.
  - In a packaged install the token lands beside the code (read-only under
    Program Files, so `token_save_failed` and auth never persists).
  - The core conftest's temp-root redirect doesn't cover it.
- **Secondary:** the token file is written in place (not atomically) and
  created with the default umask before `chmod 600`.  That leaves a short
  window where the refresh token is world-readable, and a crash mid-write
  forces re-auth.

### P2-10. Two threads can switch capture streams at once

**Where:**
- `unicornviz/audio/capture.py:1232-1293`.
- Auto-fallback moved onto the analysis thread on 2026-09-22
  (`manager.py:357`).

**What happens:** operator `select_source` / `cycle_source` run on the main
thread (in-process) or the helper's command thread; `_collect_probe_result`
→ `_switch_to_candidate_index` runs on the analysis thread.  Neither takes
a lock around `_stream`, `_reader_thread` and `_candidate_index`.

The collision is most likely exactly when it matters: the current source
is silent, so the fallback probes, and the operator reaches for the
selector.  Two concurrent open/close sequences can double-open PortAudio.
The code's own comments tie that to heap-corruption aborts.

**Fix direction:** one `threading.Lock` around the whole switch
(stop-reader → close → open) and around `stop()`.

## Policy gaps noticed (not bugs)

- **Path containment.**  CLAUDE.md says config paths "must stay within the
  project root or explicitly whitelisted directories".  `paths.resolve_path`
  has no containment check, and absolute paths pass straight through.
  Config is operator-trusted, so this is a documentation/code mismatch
  rather than a hole.
- **Runtime network access.**  CLAUDE.md says "the main application does not
  make network requests at runtime".  lyrics-01 (LRCLIB), spotify-01 and
  chat-01 do, by design.  The rule should name its drop-in exceptions.

## Noted for the performance pass (not bugs; not pursued)

- `RuntimeStateStore.set()` rewrites the whole JSON file synchronously on
  every call.  Config-editor slider notches and drags call it per step on
  the main thread.
- `AudioCapture._collect_probe_result` → `_switch_to_candidate_index` opens
  and closes PortAudio streams on the analysis thread (up to the close
  timeout).
- `MidiManager.maintenance_update` enumerates ALSA sequencer ports on the
  main thread every interval.
- `Recorder.start` resolves the audio source (`pactl`) and, without a
  prewarm, runs the hardware-encoder probe on the main thread.
- The mixer writer loop allocates a `(frames, 4)` array per block when
  4-channel headphone output is on.

## What this audit did not do

- It did not exercise hardware (APC, DDJ-REV1, S4 MK3, cameras), a real GL
  driver, Windows, or network drop-ins against live services.
- It did not read every line of `overlays.py`, dj-mixer-01's `ui.py`, the
  full Auto VJ director/recommender, training-kit-01's tools, or each
  effect shader.  Those were covered by the mechanical sweeps and targeted
  greps only.
- The P1/P2 items marked VERIFIED have reproductions in the audit seat.
  The others cite the exact lines and should get a regression test in the
  same commit as their fix, per the project's test discipline.
