Patched **free-threaded CPython 3.14 (cp314t)** wheels for Unicorn Viz, **Linux x86-64 (manylinux_2_28) and Windows x86-64 (win_amd64)**: python-rtmidi, glcontext, moderngl, sphn and opencv-python-headless. Each is the same package and version as the wheel in the earlier releases (`wheelhouse-cp314t-2026-10-01`, `wheelhouse-cp314t-win-2026-10-01`) rebuilt from patched sources, so that importing it no longer turns the GIL back on and the known thread-safety bugs are fixed. A PEP 427 build tag makes pip prefer these over the earlier builds.

**This is not an app release.** It is an append-only wheel store: assets are never replaced or deleted. The trust anchor is `tools/packaging/wheelhouse-cp314t.sha256` in the repository; builds refuse any asset that does not match it (`tools/packaging/fetch_wheelhouse.sh`). The `SHA256SUMS` asset here is a convenience copy.

The changes are ours, offered upstream under each project's own license. **The vendored libraries are unchanged from the earlier wheels**, so their license facts carry over. Checked 2026-10-02 by comparing every vendored shared library / DLL (name and sha256) and every license file in each patched wheel against its predecessor, both platforms: all identical (the Windows OpenCV `LICENSE*.txt` differ only in CRLF vs LF line endings). For sphn, the patched build uses the same PyPI sdist, `Cargo.lock` and `--locked` build with a one-line source change; a comparison of the crate paths embedded in the original and patched binaries found identical sets (a partial check, since only some crates leave a path), so `sphn-0.2.1-THIRD-PARTY-NOTICES.md` is carried over for `sphn-0.2.1-1`:
- Linux OpenCV wheel: FFmpeg 8.0.1 (plain LGPL 2.1+, no `--enable-gpl`/`--enable-version3`/`--enable-nonfree`, shared `.so` files under `opencv_python_headless.libs/`, replaceable), libvpx v1.15.2 (BSD) and libdrm 2.4.115 (MIT). FFmpeg configure flags and source pointers are in the notes of `wheelhouse-cp314t-2026-10-01`; the libdrm license text is the `libdrm-2.4.115-NOTICE.txt` asset here.
- Windows OpenCV wheel: FFmpeg 4.4.6 + libvpx v1.15.2 + aom v3.13.1 in the separate, replaceable, unmodified `cv2/opencv_videoio_ffmpeg4130_64.dll` (LGPL 2.1+), see `opencv-windows-ffmpeg-plugin-NOTICE.txt` (attached; it reproduces the libvpx and aom license texts that OpenCV's own LICENSE-3RD-PARTY.txt omits for Windows).
- Windows rtmidi / glcontext / moderngl / sphn wheels: one `.pyd` each, no bundled DLLs; rtmidi uses WinMM (a system component).

**Build.** Linux wheels: the `quay.io/pypa/manylinux_2_28_x86_64` image (GCC 14), free-threaded CPython 3.14.7, `auditwheel` repair, smoke-tested on python-build-standalone 20260929 / 3.14.7 free-threaded. Windows wheels: GitHub Actions `windows-2022` (MSVC 14.44) in a private build repository, same python-build-standalone runtime. With all five patched wheels installed, importing `cv2`, `rtmidi`, `glcontext.*`, `moderngl` and `sphn` keeps the GIL off. Provenance is recorded in `docs/planning/free-threaded-wheels-2026-09-30.md` (patched-wheels section).
